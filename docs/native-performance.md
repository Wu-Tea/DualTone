# 原生版性能实测

在同一台机器和当前声音配置下，v0.2.1 原生版相对 v0.1 降低了 CPU 占用和副路数字转发延迟。GUI 工作集没有同比减少，详细调节窗口的工作集反而更高；纯 CLI 后台的内存下降明显。

## CPU 与内存

下表为各模式有效运行的平均值。所有模式均在处理副音频；“详细窗口”同时打开主面板和详细调节窗口。“纯 CLI 后台”不加载 GUI，不等同于把 GUI 收至托盘。

| 状态 | CPU：v0.1 → v0.2.1 | 工作集：v0.1 → v0.2.1 |
|---|---:|---:|
| 主面板 | 1.01% → 0.34%，下降 66% | 242.7 → 236.7 MiB，下降 2.5% |
| 详细窗口 | 1.86% → 0.75%，下降 59% | 258.1 → 285.5 MiB，增加 10.6% |
| 纯 CLI 后台 | 0.30% → 0.17%，下降 45% | 138.0 → 19.0 MiB，下降 86% |

CPU 使用进程及其子进程的累计 CPU 时间差，除以采样墙钟时间及 20 个逻辑处理器。该口径不保证与任务管理器的瞬时 CPU 数字完全一致。工作集是驻留物理内存，包含共享页；摘要中的 `private_commit_mib` 是专用提交量，不能当成实际物理内存使用量。

## 副路延迟

每版主面板分别启动三轮，每轮测量两次。

| 指标 | v0.1 | v0.2.1 |
|---|---:|---:|
| 中位数 | 16.6735 ms | 8.2850 ms |
| 范围 | 12.954–20.088 ms | 5.285–9.821 ms |
| 有效测量 | 6 / 6 | 6 / 6 |

中位数减少 8.3885 ms，约 50.3%。全部测量通过时间戳、包间连续性和相关性检查，相关系数最低 0.9994；无捕获中断或时间戳错误。

两版都使用仓库同一个外部 `measure_latency.py` 测量器，以 WASAPI QPC 时间戳和匹配 DSP 的源信号做相关分析，没有使用两版各自的 CLI 测量实现作比较。这是数字转发估计，排除了参考滤波器群延迟，不包含完整的显示器内部处理、扬声器及声学传播延迟。结果有启动周期波动，不是声学同步或长期延迟上限保证。

## 条件与步骤

- CPU：Intel Core i5-13600KF，14 核、20 逻辑处理器。
- 比较实际免安装包中的 v0.1 Python/Qt 与 v0.2.1 C++/Slint 可执行文件，二进制 SHA-256 见摘要。
- 路由：CX31993+97220 USB 小尾巴，96 kHz → Odyssey G65B DP，48 kHz；立体声原生混音格式。
- 两版使用相同配置副本：十段 EQ 关闭，单段 50–8000 Hz 过滤开启，空间补充开启；副路增益约 25.77%，空间强度约 91.83%。未对主路增加同步缓冲。
- 固定种子的低音量立体声测试序列（峰值 0.003）与用户正在播放的内容混合。播放持续进行，因此各轮并非完全相同的隔离音频样本；这是本机交替实测，不是实验室基准。
- 每轮启动后预热 4 秒，再采样约 15 秒，每秒记录一次进程资源。外部信号生成器、测量器和 CLI 控制进程不计入被测应用资源。
- 主面板顺序：旧、新、新、旧、旧、新；详细窗口：新、旧、旧、新；后台：旧、新、新、旧。共 14 轮有效资源采样。延迟测量在资源采样结束后进行。
- 一次旧版详细窗口启动时控制接口未响应，该次未产生有效资源数据；测试退出并恢复原状态后续测，最终补齐全部计划轮次。
- 完成后核对 Windows 三个默认输出角色及用户配置未改变，并恢复原生 GUI 和此前的静音对比状态。
